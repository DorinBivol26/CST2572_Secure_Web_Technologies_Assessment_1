# Data, PWA and integration contribution

As the Data, PWA and integration lead, I designed and implemented the client-side data layer and offline application foundation for the CareLocal application. This work supports the assessment requirements for IndexedDB, JSON processing, CRUD operations, progressive web application features and the entity-relationship diagram.

The application uses an IndexedDB database named `carelocal`. It contains seven object stores: `patients`, `doctors`, `admins`, `medicines`, `appointments`, `notes` and `prescriptions`. Each store uses an `id` key path, allowing records to be inserted, updated and retrieved consistently. Patient records contain personal and contact information such as name, address, telephone number, date of birth and NHS number. Appointments link patients and doctors, while notes and prescriptions store clinical information associated with patients. Prescriptions also reference medicines and include usage instructions.

The reusable database functions are contained in `db.js`. They open the database, read records, insert or update records, delete records and import groups of records through a read/write transaction. This creates one shared data layer for the application rather than separate temporary data in each page. The Admin demonstration view uses these functions to add, edit and delete patients. The Patient view stores appointments, and the Doctor view stores clinical notes and prescriptions. These operations were verified in Chrome DevTools by inspecting the relevant IndexedDB object stores.

The JSON import process in `app.js` attempts to fetch the assessment feeds for doctors, patients, administrators and medicines. The responses are converted into arrays and written to IndexedDB. During testing, the supplied URLs returned HTTP 404 responses and some requests were also affected by cross-origin restrictions. To keep the application usable and testable, clearly labelled local seed records are used when a feed is unavailable. The interface reports that fallback data is active, rather than presenting it as live server data. The same import path can be used with corrected URLs.

I also implemented the PWA foundation. `manifest.json` defines the application name, start URL, display mode and theme. The service worker in `sw.js` caches the application shell and successful runtime requests. Chrome testing confirmed that the application remained available after switching the Network panel to Offline mode. IndexedDB provides persistent local records, while Cache Storage provides the application assets.

The ER diagram documents relationships between patients, doctors, medicines, appointments, notes and prescriptions. My contribution was tested through VS Code Live Server in Google Chrome. The database, seven stores, CRUD operations, service worker, cache and offline shell were all verified. Authentication, authorization, password security, AES-256 encryption and final interface ownership remain team integration responsibilities.

For evidence, screenshots were captured of the CareLocal interface, the IndexedDB database and its object stores, stored records, the active service worker, Cache Storage and the application operating in Offline mode. The implementation was committed to the shared `main` branch so that teammates can integrate their account and security features without creating a second database. The README explains how to run the application through a local web server and why `file://` should not be used for service-worker testing. This provides a reproducible handover and makes the data layer available to the complete project.
